# 日记版记忆瓶合并与性能修复 Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:executing-plans to implement this plan inline with one final independent review.

**Goal:** 恢复用户的 EMMO 日记版及最新个人页、转盘更新，合入顺滑记忆瓶，并上传新的体验版。

**Architecture:** 以 emmo-journal 当前源码为唯一基线，在隔离 worktree 合并。
只迁入记忆瓶模块和小入口，不用旧 3.0 页面替换 3.1 页面。
缓存瓶身/表情绘制，按屏幕帧回调更新，并减少碰撞的重复计算。

**Tech Stack:** 微信原生 TypeScript/WXML/WXSS、Canvas 2D、原有 Repository 与 TDesign。

**Spec:** 用户本轮已明确选择「日记版＋最新个人页和转盘」，并授权优化后上传体验版。

## Global Constraints

- 保留 4 个 Tab、心情日历、日记草稿、相册、位置选择、最新个人页及心情/主题转盘。
- 保留原有数据、云服务契约和可见范围；不部署云函数，不提交正式审核。
- 原日记源码目录不受本轮写入；合并 worktree 的既有页面采用最小补丁。
- 物理边界、点击、60 条分页、传感器归属与生命周期安全仍须通过。
- 上传前逐项核对基线功能、源代码哈希与体验版版本；不能仅依据旧目录或版本名称。
- 手机实机帧率不得用桌面或模拟器数字代替。

## Review Focus

- 最新个人页和转盘的并发修复不得被覆盖。
- 60/120Hz 时间戳都应持续绘制，不保留 28ms 的主动限帧。
- 缓存不可用时可降级；缓存的表情/颜色随翻页或记录编辑更新。
- 传感器晚到、退出、返回、Canvas 重建不能产生多重动画或残留监听。
- 更高刷新率下运动速度、碰撞和触摸坐标应保持正确。
