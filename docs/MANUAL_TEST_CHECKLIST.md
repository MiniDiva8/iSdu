## 2. 导入、构建与编译

1. 在微信开发者工具选择“导入项目”。
2. 选择仓库根目录，即包含 `project.config.json`、`package.json` 和 `miniprogram` 的那一级，不要只选择 `miniprogram`。
3. 公共配置只应出现 `touristappid`。预览和真机调试请在本机填写自己的 AppID，不要提交该改动。
4. 选择“工具 → 构建 npm”。
5. 确认 TDesign 被构建到 `miniprogram/miniprogram_npm`，没有把 `node_modules` 复制进源码。
6. 点击“编译”。
7. 确认默认进入“地图”Tab，页面不是白屏，TDesign Button 正常显示。
8. 打开 Console，确认没有编译阻断、资源 404、未处理 Promise 或持续事件异常。

## 5. 中心准星选点校准

### 默认比例校准

1. 点击“回到初始位置”。
2. 点击“记录此处”。
3. 不拖动、不缩放，直接确认。
4. 编辑页位置应接近横向 `50.0%`、纵向 `50.0%`。
5. 取消返回。

### 缩放原点回归

1. 回到初始位置。
2. 在视口中心附近执行放大，尽量不平移地图。
3. 让同一地图地点仍停在准星下，分别在约 `1×` 和 `2×` 确认。
4. 两次比例差应很小；若 `2×` 结果接近原比例的一半，说明错误使用了左上角缩放公式，必须阻断验收。

### 已知标记校准

1. 先创建一个位置明确的测试星点，再把它准确移到准星中心。
2. 在 `1×`、中间比例和接近 `2.5×` 各确认一次。
3. 三次结果建议在横纵各 `0.005` 以内。

### 新建后标记回显校准

1. 选择一个轮廓明确的小建筑角点，让准星中心与该角点重合。
2. 保存一条文字日记并返回地图。
3. 不移动地图，确认新标记中心与刚才准星位置重合，不能落到另一栋建筑。
4. 删除该测试记录，分别在约 `1×`、`1.7×` 和 `2.5×` 重复测试。
5. iOS 和 Android 真机各执行一次；任何一次相隔明显建筑距离都视为阻断缺陷。

- [ ] 选点时准星固定在实际地图视口中心。
- [ ] 选点时地图没有确认后的惯性滑动。
- [ ] 连续点击“确认位置”只打开一个编辑页。
- [ ] 屏幕尺寸变化会取消当前选点，不保存旧几何下的坐标。

## 6. 新建文字日记

1. 地图点击“记录此处”，移动到明确地点后确认。
2. 不选照片，填写正文、地点，选择心情和分类。
3. 点击“保存回忆”。
4. 保存时再次快速点击，确认不会生成重复日记。
5. 返回地图后，新位置立即出现分类色发光星点。
6. 点击星点，卡片的标题、日期、地点、心情和分类正确。

- [ ] 仅文字可以保存。
- [ ] 正文和照片都为空时被阻止。
- [ ] 正文最多 2000 字。
- [ ] 地点最多 60 字，地点为空也可保存。
- [ ] 保存过程有 loading，失败有明确提示。

## 7. 新建照片日记与权限

分别测试“从相册选择”和“拍照”（设备支持时）：

1. 新建回忆，选择 1 张照片并填写少量文字后保存。
2. 再新建一条，只选择照片、不写正文，确认可以保存。
3. 新建第三条，连续添加到 3 张，确认不能添加第 4 张。
4. 打开图片选择器后取消，确认页面内容不丢失且不显示错误。
5. 点击“添加照片”，确认先出现用途说明；点“暂不添加”后仍可继续写文字。
6. 再次点击并继续选择，拒绝相册权限一次，确认页面显示可理解的错误而不是白屏。

- [ ] 地图星点优先显示第一张照片。
- [ ] 详情页可以查看全部照片。
- [ ] Storage 中保存的是用户目录持久路径，不是 `wx.chooseMedia` 临时路径。
- [ ] Storage 中没有 Base64 图片。
- [ ] 任一图片复制失败时，该日记不会保存无效路径。

3. 进入地图并点击两个星点。
4. 进入详情查看照片和文字。
5. 真机上再执行一次前后台切换和微信进程重开。

- [ ] 持久化照片仍可显示。

## 9. 详情与编辑

1. 从地图星点进入详情。
2. 确认照片、正文、日期时间、地点、心情、分类和比例位置均正确。
3. 点击“编辑”。
4. 修改文字、地点、心情和分类。
5. 删除一张旧照片，添加一张新照片并保存。
6. 返回详情，再返回地图。

- [ ] 编辑页完整回显原值。
- [ ] 地图比例默认保持不变。
- [ ] 详情在 `onShow` 后显示最新内容。
- [ ] 地图星点的颜色、照片和卡片立即更新。
- [ ] 被移除的旧照片在 Repository 更新成功后才清理。
- [ ] 编辑中点击取消或系统返回会提示未保存内容。

## 10. 删除与文件清理

1. 打开一条带照片的日记详情。
2. 点击删除，先点“取消”，确认数据仍在。
3. 再次删除并确认。
4. 返回地图后确认星点立即消失。
5. 检查 Storage 中对应 Memory 已删除。
6. 如开发者工具可查看用户文件目录，确认不再被其他 Memory 引用的照片已删除。

- [ ] 删除有二次确认。
- [ ] 删除过程中按钮锁定，不会重复执行。
- [ ] 数据删除失败时不清理仍被引用的照片。
- [ ] 数据删除成功但图片清理失败时明确提示，不静默忽略。
- [ ] 共享路径（仅用于迁移/异常测试）仍被其他 Memory 引用时不会删除。

## 11. 异常与恢复

以下操作只在可丢弃测试数据中执行，先复制原 Storage 字符串备用：

- [ ] 把 `sdu-memory:memories:v1` 改成损坏 JSON，地图显示读取错误和重试，不覆盖原值、不白屏。
- [ ] 把 `schemaVersion` 改成未知值，显示“不支持”的错误，不自动清空。
- [ ] 打开不存在的 `memoryId`，详情显示“回忆不存在”并能返回地图。
- [ ] 临时移走一张受管照片，地图降级为星点，详情显示缺图，编辑要求移除或重选。
- [ ] 使用非法比例的测试记录时，该记录被过滤并显示异常数量。
- [ ] 点击“测试地图加载失败状态”，出现错误覆盖层；点击重试后恢复。

完成后恢复或清除测试 Storage，不要保留故意损坏的数据。

## 16. 地图放大拖动边界

1. 将地图放大到约 `1.5×`、`2×` 和最大 `2.5×`，分别向四个方向缓慢拖动。

3. 快速甩动地图，确认普通浏览模式的惯性平滑停止，地图不会无限移出视口。
4. 在最小 `1×` 缩放下分别向四个方向用力拖动并松手，确认最多只留下很窄的边缘空隙，不会出现半屏或大半屏空白。
5. 进入选点模式并重复上述操作，确认关闭惯性后仍能把地图四角移动到中央准星。

7. iOS 和 Android 至少各验证一次双指缩放后的拖动。

- [ ] 放大后可连续浏览整张地图，没有内部“空气墙”。
- [ ] 松手不会发生与手势方向相反的大幅回弹。
- [ ] 地图不会无限拖走，中心准星不会停在画布之外后仍允许保存。
- [ ] 普通浏览模式松手后地图重新覆盖视口，不会停留在大片浅绿色空白区域。

- [ ] 取消清除不修改任何数据。
- [ ] 成功后 Memory 快照为空、个人资料键移除、受管照片目录删除。
- [ ] 部分失败时不显示虚假的“全部成功”。
