# iSDU 项目与技术导读

[返回项目首页](../README.md) · [文档导航](README.md) · [比赛介绍 PPT](https://github.com/MiniDiva8/iSdu/releases/tag/competition-v2)

## 用一分钟了解项目

iSDU 是一个以校园地点组织照片与文字的微信原生小程序。用户在插画地图上手动选点记录生活，通过地图和按月时间轴回顾；开启云功能后，可以经双方确认建立好友关系，并控制每条回忆的分享范围。

一个典型场景是：在校园某处拍下照片，把它保存到地图上的对应位置；数月后按月份找到这条记录，再跳回地图；希望分享时，只授权给指定好友。

项目的工程价值在于把地图交互、数据恢复、身份授权与多视图查询连成可运行的闭环。以下以默认分支 Social V2 的代码为依据。

## 1. 地图交互：让位置在不同视图中保持一致

**问题：** 屏幕像素位置随设备、拖动与缩放变化，不能直接作为日记的永久位置。开发者工具和真机对变换事件的表现也可能不同。

**实现：**

- 使用相对原始地图的 `xRatio`、`yRatio`，范围均为 `[0, 1]`。
- 选点时读取地图图片与可视区域的实际渲染矩形，以中心准星计算位置。
- 标记与底图处于相同变换容器；时间轴跳回地图时使用保存的比例坐标。
- 保存地图版本，避免把旧版地图坐标错误投影到新建筑位置。

**可检查的证据：** [坐标设计](MAP_COORDINATE_SYSTEM.md)、[坐标纯函数](../miniprogram/utils/map-coordinates.ts)、[边界与变换测试](../miniprogram/utils/map-coordinates.test.mjs)、[地图页面](../miniprogram/pages/map/index.ts)。

**取舍：** 采用手动选点的二维校园地图，不依赖 GPS；更适合地点记忆，也限定了当前单校区、单底图的使用范围。

## 2. 好友共享：把权限放在服务端

**问题：** 仅在界面隐藏内容无法阻止越权读取；分享后删除好友、撤回授权或重新建立关系，旧授权也需要正确失效。

**实现：**

- 云函数使用可信调用上下文识别用户，不把客户端传入的作者或查看者 ID 当作授权依据。
- 回忆分为仅自己、指定好友、全部好友三档，默认私密。
- 读取详情、好友地图、好友时光和点赞前分别校验权限与当前好友关系。
- 指定好友授权绑定 `relationshipId`，删除后重新加好友不会自动恢复旧的指定授权。
- 图片通过鉴权后签发短期地址；数据库保存 `fileID`。
- 点赞使用唯一配对键和事务处理，避免重复请求产生多条有效点赞。

**可检查的证据：** [Social V2 设计](SOCIAL_V2_DESIGN.md)、[回忆处理器](../cloudfunctions/memory-api/lib/memory-handler.js)、[存储与事务](../cloudfunctions/memory-api/lib/cloud-memory-store.js)、[权限测试](../cloudfunctions/memory-api/lib/memory-handler.test.cjs)。

**取舍：** 已签发的图片地址具有有效期，撤回权限不能追溯收回已下载图片；服务端授权和短期地址分别承担不同的保护作用。

## 3. 本地与云端：迁移失败时保留可恢复的数据

**问题：** 照片保存、云端上传和数据库写入可能分别失败。迁移中途切换数据源，容易让用户误以为原记录丢失。

**实现：**

- 本地照片先进入小程序用户文件目录，并处理保存回滚、旧文件清理和缺失文件。
- 云端迁移只处理用户记录，默认设为私密，保留本地副本。
- 单条迁移执行云端回读与图片数量核验；汇总全部成功后才激活云端数据模式。
- 部分失败返回逐条失败结果，云端写入失败不静默变成本地写入。

**可检查的证据：** [本地数据设计](LOCAL_DATA_DESIGN.md)、[照片服务](../miniprogram/services/local-image-service.ts)、[迁移流程](../miniprogram/services/memory-migration-service.ts)、[云端回读](../miniprogram/services/repository/cloud-memory-repository.ts)、[迁移测试](../miniprogram/services/memory-migration-service.test.mjs)。

**取舍：** 本地模式与云端模式有明确切换，本项目不宣称支持完整的离线多端同步或自动冲突合并。

## 4. 工程组织：让核心逻辑可独立验证

页面承担交互与展示，Service 组织业务流程，Repository 封装本地和云端数据访问。坐标、筛选与统计等纯逻辑可以在 Node.js 中测试，云函数处理器通过可替换依赖验证授权与错误分支。

质量入口是 [package.json](../package.json) 中的 `npm run check`：

1. 运行坐标、记录、图片、身份、好友与云端回忆测试。
2. 执行 TypeScript 类型检查和 ESLint。
3. 检查 TypeScript、WXML、WXSS 与文档格式。
4. 扫描敏感配置、异常大文件与云函数依赖版本。

测试覆盖是代码层面的证据。云函数实际部署配置、真实设备体验和跨账号安全矩阵仍需分别验证。

## 五分钟演示路线

| 时间      | 操作                                                 | 希望说明的能力           |
| --------- | ---------------------------------------------------- | ------------------------ |
| 第 1 分钟 | 拖动、缩放地图，选择一个地点                         | 地图交互与比例坐标       |
| 第 2 分钟 | 添加照片、文字与心情，保存后点开标记                 | 空间日记完整闭环         |
| 第 3 分钟 | 在时光中搜索、按月回顾，再定位到地图                 | 时间与空间两个视图的连接 |
| 第 4 分钟 | 用已准备的两个账号展示好友邀请、授权记录与点赞       | 服务端权限与好友共享     |
| 第 5 分钟 | 将共享改回私密，另一账号刷新后验证访问；展示对应测试 | 权限撤销与工程验证       |

前 3 分钟可在本地模式演示。后 2 分钟需要已配置的 CloudBase、两个有访问资格的微信账号和事先准备的测试记录；实际结果以当次演示为准。

## 可继续研究的问题

该项目可以作为人机交互、空间信息组织与隐私权限设计的实践基础：

- 地图与时间轴结合，是否比单一时间列表更有助于找回校园记忆？
- 记忆点增多时，聚合与筛选怎样影响查找效率和操作负担？
- 用户是否准确理解三档共享权限，以及撤销和重新建立好友关系的后果？

以上是可进一步开展用户实验的问题，尚未给出对照实验、统计显著性或规模化使用结论。
