# iSdu 双向好友配置与验收

iSdu 好友由双方通过一次性邀请主动建立。该功能不读取微信通讯录、微信好友列表、手机号或微信号。

## 集合与索引

以下集合全部设置为“小程序端不可直接读写”，仅允许云函数管理端 SDK 访问：

- `friendships`
- `friend_requests`
- `invite_tokens`
- `likes`

创建唯一索引：

| 集合            | 字段        | 说明                               |
| --------------- | ----------- | ---------------------------------- |
| `friendships`   | `pairKey`   | 每对 iSdu 用户只有一条关系记录     |
| `invite_tokens` | `tokenHash` | 数据库不保存分享卡片中的原始 Token |
| `likes`         | `pairKey`   | 每位好友对一段回忆最多一条点赞记录 |

创建普通索引：

- `friendships.userAId + status`
- `friendships.userBId + status`
- `invite_tokens.creatorUserId + createdAt`
- `invite_tokens.expiresAt + usedAt`
- `likes.memoryId + userId`
- `likes.ownerUserId + userId`

## 邀请安全规则

- 邀请有效期 24 小时、只能使用一次，10 分钟内最多创建 5 个。
- 分享卡片包含随机原始 Token；数据库只保存 SHA-256 哈希。
- 接收者打开卡片只看到邀请者名字与签名，必须再点击“接受邀请”。
- 服务端阻止自邀、过期邀请、被他人重复使用和重复好友关系。
- 好友关系保存随机 `relationshipId`。删除后再次添加会生成新 ID，过去的“部分好友”授权不会自动恢复。

## 回忆可见范围

- `private`：仅作者可读取。
- `friends`：当前仍有效的任意 iSdu 好友可读取。
- `selected_friends`：服务端把所选好友转换为 `{ friendUserId, relationshipId }` 授权快照。

页面提交的 userId 只是选择意图，`memory-api` 会重新查询当前有效好友关系。删除后即使再次添加同一用户，新关系 ID 也无法匹配旧授权。回忆第一次由私密改为共享时，由服务端写入 `publishedAt`；客户端不能回填或修改该时间。

## 点赞与图片读取

- 好友详情先重新检查当前好友关系、可见范围和 `relationshipId`，通过后才为私密 fileID 签发短期图片地址。
- 点赞与取消点赞在事务中再次执行同一权限判断，并同步更新唯一点赞记录与 `likeCount`。
- 作者本人、已删除好友、私密回忆以及未被选中的好友都不能点赞。
- 删除好友会清理双方之间仍有效的点赞并回减计数。
- 客户端只得到 `likeCount` 和 `likedByMe`，不会得到点赞用户列表或永久图片 URL。

## 好友近 24 小时地图

- 地图默认仍显示“我的回忆”；“好友 24h”是用户主动切换的独立图层。
- 查询以服务端第一次共享时写入的 `publishedAt` 为准，边界包含恰好 24 小时。
- 服务端按最多 20 位好友分批查询，结果每页最多 50 个点；客户端使用游标继续读取。
- 轻量点只包含作者显示名、地点、心情、分类、比例坐标、地图版本和发布时间，不返回正文、照片、fileID 或点赞列表。
- 点击圆点后重新请求共享详情并再次鉴权，只有这一步才签发短期图片地址。
- 私密、关系已删除、部分好友授权失效、非法坐标、旧地图版本和超过 24 小时的回忆都不会返回。

## 部署与人工验收

1. 先完成 `auth-api` 的双账号身份隔离验证。
2. 创建集合和索引，部署 `friend-api` 并选择云端安装依赖。
3. 账号 A 在“时光 → 好友”生成邀请，并通过微信分享给账号 B。
4. B 打开后确认不会自动建立关系，点击接受后双方列表各出现一条记录。
5. 重复点击接受，确认没有第二条 `friendships` 记录。
6. A 尝试打开自己的邀请，确认被拒绝。
7. 修改测试邀请过期时间，确认过期邀请不能接受。
8. 删除好友，确认双方刷新后关系消失。
9. 再次添加，确认新的 `relationshipId` 与删除前不同。
10. 分别保存“仅自己、部分好友、全部好友”，并验证部分好友未选择任何人时不能保存可见范围。
11. B 对有权回忆点赞、取消并快速重复操作，确认计数不会重复累加。
12. A 改为私密或删除 B，确认 B 的详情、图片与点赞请求立即失败。
13. 切换“好友 24h”图层，确认只显示过去 24 小时且当前有权访问的小圆点。
14. 修改权限、删除好友或模拟超过 24 小时后刷新，确认圆点立即消失。

真实双账号验证完成前，只能标记“好友代码与自动测试完成，真实关系安全待验收”。
