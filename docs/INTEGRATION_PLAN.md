# 第三方集成计划

> 执行状态（2026-07-31）：步骤 1 的代码与命令行检查已完成；步骤 2 已锁定并安装 `tdesign-miniprogram@1.15.3`，只注册 Button 和 Empty。微信开发者工具构建 npm、包体记录和真机验证仍待人工完成。

## 1. 集成原则

- 只集成对当前里程碑有直接价值的内容。
- 正式运行时依赖只保留一套 UI 组件库。
- 默认从最小骨架自行实现，不把示例仓库当项目底座。
- 许可证、版权、来源和修改记录必须可追溯。
- 每一步都必须可独立验证和回滚。
- 依赖安装必须由具体里程碑授权；本轮已获准安装精确锁定的 TDesign 与最小质量工具，仍不授权复制第三方仓库源码。

## 3. 允许的局部迁移规则

当前没有“无需复核即可迁移”的代码。

如未来确需从微信官方示例迁移少量通用代码，必须按以下流程：

1. 在任务说明中列出仓库、分支/提交、准确文件路径和目标函数。
2. 再次核实该文件受根 MIT 许可证覆盖。
3. 只迁移实现当前 P0 所需的最小片段；优先按当前项目类型和错误模型重写。
4. 在目标文件相邻注释中写明来源 URL、提交 SHA、许可证和修改情况。
5. 更新 `docs/THIRD_PARTY_NOTICES.md`。
6. 在 diff 中单独审查，不与大量原创业务代码混合。
7. 保留版权和 MIT 文本；不得删除原作者信息。

参考交互思路、目录职责或公开截图而没有复制表达形式时，也应在设计/决策文档中保留来源，但不要把第三方截图或素材打包进作品。

## 4. 集成顺序与回滚

### 步骤 0：接受本轮文档

产物：项目规则、评估、技术决策、风险和下一任务提示词。

验收：

- 12 个仓库均有明确分类和评分。
- 未引入依赖、第三方源码、AppID 或云配置。

回滚：

- 文档均为独立新增文件，可按文件回退；不得影响业务代码，因为业务代码尚不存在。

### 步骤 1：最小原生 TypeScript 骨架

范围：

- 创建最小小程序目录、一个工程验证页和基础配置。
- 使用占位/游客 AppID 配置，真实 AppID 只进入私有配置。
- TypeScript、ESLint、Prettier 能运行。

验收：

- 微信开发者工具可打开并编译。
- 命令行类型、Lint、格式检查通过。
- 不包含地图、日记或 CloudBase 逻辑。

回滚：

- 保持单独提交；回退该提交即可恢复到纯文档状态。

### 步骤 2：按需集成 TDesign 基础组件

范围：

- 固定并安装经核实的精确版本。
- 先只注册 Button、Loading、Empty/Toast 等工程验证需要的少量组件。
- 建立最小设计 token。

验收：

- 开发者工具构建 npm 成功。
- 模拟器和至少一台真机的组件显示/点击正常。
- 记录安装前后构建包体。
- `THIRD_PARTY_NOTICES.md` 从“候选”更新为“已使用”。

回滚：

- 删除页面注册和依赖，恢复 lockfile 与第三方声明的前一状态。
- 不在同一步用 Vant 或 WeUI 替换；若 TDesign 阻断，先形成新决策。

### 步骤 3：本地 Demo 数据层

范围：

- 定义 Diary、MapPoint、Photo 和 Repository 类型。
- 实现版本化本地 Repository、Seed 和损坏数据恢复。
- 不创建正式业务页面。

验收：

- CRUD、schema 校验和迁移的单元测试通过。
- 清空/损坏本地存储有明确错误处理。

回滚：

- Repository 接口与本地实现独立提交；回退不影响 UI 骨架。

### 步骤 4：插画地图技术样片

范围：

- 使用占位图验证拖动、缩放、复位、选点和标记。
- 实现比例坐标纯函数和测试。
- 不接 CloudBase，不制作正式校园地图。

验收：

- 多尺寸和真机没有明显漂移。
- 往返转换误差在预先确定的容差内。
- 无定位权限。

回滚：

- 地图组件、坐标工具和技术样片保持独立提交；可整体撤销，不影响数据层。

### 步骤 5：P0 本地闭环

按地图 → 编辑 → 详情 → 时间轴 → 概览的顺序实施，每个页面带空、加载、错误状态和人工测试记录。每个子步骤独立提交，不提前进入 P1。

### 步骤 6：CloudBase 接入

前置条件：

- P0 本地闭环已经通过。
- 用户提供私有 AppID/环境并批准云资源操作。
- 单独审查 CloudBase Skills/MCP 是否有必要。

范围：

- 实现 Cloud Repository。
- 集合和存储均为仅创建者可读写。
- 图片保存 `fileID`。
- 用两个用户做越权反向测试。

回滚：

- 本地 Repository 始终保留；切回本地模式即可保证 Demo。
- 云端 schema/rules 变更前导出或记录旧配置，禁止不可逆覆盖。

### 步骤 7：P1 与比赛包装

只有 P0 测试全部通过后，按优先级加入月份筛选/时光回放，再进行正式插画、五分钟 Demo、PPT 和性能整理。

## 5. 包体控制

- UI 组件只在页面 JSON 按需注册，不全局注册组件全集。
- 不安装 Vant、WeUI、uView 或其他第二套组件库。
- 不复制 TDesign 示例、文档站、Pro/Chat/uni-app 产物。
- 每个依赖步骤记录构建后的主包/总包数据，以开发者工具结果为准。
- 依赖安装后检查 `miniprogram_npm` 的实际产物，不用 npm 解包体积替代最终包体。
- 原始照片不进入代码包；演示 Seed 图片压缩并限制数量。
- 正式地图按目标屏幕和缩放需求导出，避免未经优化的超大 PNG。
- P0 完成后再评估分包，不为“可能有用”提前增加分包复杂度。

## 6. 避免无关业务

- 不从 retail starter 复制页面目录，只借鉴职责命名。
- 不从日记项目复制用户、粉丝、关注、收藏、管理员或公开内容。
- 不从 CloudBase 示例复制论坛、商城、AI、视频、社交或管理后台。
- 新增页面必须能映射到 `AGENTS.md` 的 P0/P1 清单；无法映射的需求先停止。
- 代码评审检查关键词：`comment`、`like`、`follow`、`feed`、`nearby`、`gps`、`admin`、`recommend`，发现后确认是否越界。

## 7. 视觉统一

- 在项目内定义一套设计 token：校园绿/暖纸色/墨色、间距、圆角、阴影、字体层级和动效时长。
- TDesign 组件只提供行为和基础结构，页面不得混入 Vant/WeUI 类名或零售模板主题。
- 自研业务组件统一封装记忆标记、照片卡片、状态页和月份标题。
- 第三方截图只用于研究，不进入资源目录。
- 关键页面以地图为视觉主角；表单和弹层保持克制，避免企业后台或商城感。

## 8. 许可证与来源保留

- npm 依赖保留包内 LICENSE，并在本仓库第三方声明中记录名称、版本、来源和 MIT。
- 迁移代码保留源文件版权和许可证，在相邻注释记录提交 SHA。
- 修改第三方代码不意味着可以删除原许可；声明中写“已修改”及修改范围。
- 比赛 PPT/README 至少说明使用 TDesign、微信原生平台和 CloudBase；原创核心与第三方基础设施分开表述。
- 对许可证不清的仓库只保留研究链接，不使用代码、图片、字体或图标。
