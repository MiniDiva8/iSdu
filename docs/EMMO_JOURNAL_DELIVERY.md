## 直接导入

在微信开发者工具中导入上述项目根目录，或解压交付 ZIP 后导入含 `project.config.json` 的目录。当前 AppID 是 `touristappid`，默认本机模式。ZIP 附有已构建的 TDesign 依赖，无需先操作 npm 即可编译体验；修改或重装依赖后仍应“工具 → 构建 npm”。

## 功能与原系统的连接

| 入口       | 实际行为                                                                           |
| ---------- | ---------------------------------------------------------------------------------- |
| 日记       | 月份心情墙、同日多篇、月份切换、正文/心情/地点搜索                                 |
| 编辑       | 日期、12 种心情、文字、最多 3 张照片、分类、保存和修改、只记心情                   |
| 草稿       | 本机新建日记的文字、日期、心情、地点；明确恢复；不保留临时照片；保护其他未完成草稿 |
| 详情       | 纸张阅读、照片预览、编辑、确认删除；已关联校园地点可定位                           |
| 照片墙     | 按月展示每张照片，进入照片所属日记，长按预览                                       |
| 校园       | 现有插画地图、比例坐标、拖动缩放、本人标记、授权好友近 24 小时标记                 |
| 时光       | 原有月份回顾、搜索筛选、封面、好友时光                                             |
| 我的与好友 | 个人资料、日记统计、数据管理、好友邀请、原有分享权限和点赞                         |

好友、云端身份和照片访问继续使用原 CloudBase 服务，不新建平行的账号系统。日记默认私密，部分好友和全部好友继续由服务端按当前好友关系检查。实际跨用户操作需要真实 AppID 与云环境。

无地点日记采用显式标识 `journal-unlocated-v1`，兼容现有回忆合约；兼容坐标字段不会进入校园标记或旧版地图警告。日期墙、时光分组和记录天数统一按北京时间计算。

## 数据与失败处理

本机日记仍由既有 LocalMemoryRepository 持久化；照片使用原有本地文件保存、失效检测与失败回滚流程。云端模式不读取或自动保存本机文字草稿。恢复草稿时会明确说明照片需重选。已有另一份草稿时，新日记会保留原草稿并提示保存当前日记。

“清除全部本机数据”包含文字草稿；草稿、照片或封面清理失败会显示部分未完成，避免把敏感正文残留报告成清除成功。网络失败时新页面清除旧结果，月份切换的过期请求不覆盖新结果。
