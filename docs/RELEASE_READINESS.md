# iSdu 上线准备与发布清单

更新日期：2026-08-13

本文用于把当前本地版 iSdu 整理为可提交微信审核的版本。任何真实 AppID、AppSecret、环境 ID、管理员身份信息和私人联系方式都不得写入 Git。

## 1. 当前结论

当前仓库已经完成本地数据公测版的代码级发布加固，适合生成 `0.9.0` 发布候选并进入体验版测试；在真实 AppID、备案、类目、隐私指引、素材权利与双平台真机验收完成前，仍不能直接正式发布。

可以选择两条上线路线：

1. **本地数据公测版（较快）**：保持所有回忆和照片只保存在用户当前设备。必须显著说明换手机、清除小程序数据或卸载后可能丢失，且不同设备之间不会同步。
2. **云端正式版（推荐长期使用）**：先完成 CloudBase Repository、云存储、用户隔离安全规则、迁移和双账号越权测试，再提交正式审核。

项目规则中约定“正式模式使用 CloudBase”。因此本地数据公测版只能视为 `0.9.x`，不能宣称已经具备跨设备保存、账号找回或云端备份能力。

## 2. 当前发布门禁

### 必须完成

- [ ] 在微信公众平台注册真实小程序账号，取得真实 AppID；仓库公共配置继续保留 `touristappid`。
- [ ] 完成小程序主体认证要求和小程序备案，以公众平台当前页面要求为准。
- [ ] 设置名称、头像、简介和服务类目；类目必须与“个人校园记忆/日记工具”的实际功能一致。
- [ ] 确认 `iSdu` 名称、山东大学名称和校园地图素材具有可使用依据；没有校方授权时，不使用校徽，不宣称官方应用。
- [ ] 在微信公众平台配置《用户隐私保护指引》，声明 `wx.chooseMedia` 处理用户选中的照片信息。
- [ ] 明确发布路线：本地数据公测版或 CloudBase 正式版。
- [ ] 把当前 UI 2.0、地图边界修复和本地闭环整理为可回退的 Git 提交；提交前移除或迁出未使用的根目录大图。
- [ ] 在微信开发者工具重新“构建 npm”，并以工具显示的上传主包大小为准；主包必须满足平台限制。
- [ ] 完成一台 iOS 和一台 Android 的完整闭环测试，并填写 `docs/MANUAL_TEST_CHECKLIST.md`。
- [ ] 清除故意损坏的测试 Storage、开发用截图、测试日记和不适合审核的照片。
- [ ] 上传为体验版后，由至少一个非开发者体验成员从首次打开开始复测。

### 正式发布前强烈建议

- [x] 增加应用内“清除全部本地数据”入口，并明确二次确认和不可恢复提示。
- [x] 在“时光 → 数据管理”和照片选择前说明“当前数据仅保存在本机”。
- [ ] 为用户准备可联系的运营者邮箱，并填写到隐私保护指引和公众平台基本信息中。
- [ ] 记录地图原始文件、生成/编辑过程、提示词、日期和使用授权证据。
- [ ] 根据开发者工具“代码依赖分析”检查是否上传了未使用的 TDesign 组件。
- [ ] 关闭开发环境选项并复核正式版不存在调试入口、测试失败按钮和故意损坏资源。
- [ ] 保留一个已通过真机测试的上一版本，以便正式版出现问题时回退。

## 3. 已发现的工程现状

- 当前分支：`codex/ui-ux-2.0`。
- 当前工作区仍有大量未提交的 UI 2.0 和功能修复，不能直接把当前目录当作可追溯发布版本。
- `project.config.json` 仍使用安全占位值 `touristappid`；这是正确的仓库策略，但不能用于正式上传。
- 运行模式已调整为 `local`，`cloudEnabled=false`；正式构建不再自动灌入 Demo 日记，也没有 CloudBase、登录或网络请求。
- 当前运行源码（不含构建后的 npm）约 `740,551` 字节。
- 当前 `miniprogram_npm` 目录约 `1,451,378` 字节；两者磁盘合计约 `2,191,929` 字节。磁盘大小不等于最终上传包大小，但已经接近或超过单包限制，必须以开发者工具“上传/代码质量/依赖分析”显示结果为准。
- 校园地图 JPEG 为 `1448 × 1086`、`490,518` 字节。
- 仓库根目录的地图源图约 2.6 MB；它不在 `miniprogramRoot` 内，且已经通过 `.gitignore` 排除，不应进入发布提交。运行时只使用 `miniprogram/assets/demo/campus-map-placeholder.jpg` 中的优化 JPEG。
- `node_modules`、`miniprogram_npm` 和 `project.private.config.json` 已被 Git 忽略。
- 页面调用 `wx.chooseMedia` 选择照片；没有调用 GPS、`wx.getLocation`、微信登录、CloudBase 或外部网络请求。
- `sitemap.json` 当前禁止所有页面内容被微信索引。若希望页面内容被微信搜索，需要单独评估；这不等于小程序名称无法被搜索。

## 4. 账号与公众平台准备

1. 打开微信公众平台并注册/登录小程序账号。
2. 在“设置/基本设置”完成小程序名称、头像、简介和服务类目。
3. 以平台页面显示为准完成小程序备案；不要等到代码开发完成后才开始。
4. 在“开发管理/开发设置”查看 AppID。AppSecret 不应提供给聊天、客户端代码或 Git。
5. 把自己的微信加入项目管理员/开发成员，把其他测试微信加入体验成员。
6. 未获得山东大学官方授权时，简介建议包含：

   > iSdu 是一款非官方的个人校园记忆工具，用地图位置与时间整理仅属于你的校园回忆。

7. 不使用山东大学校徽、官方视觉标识或“官方”“校方出品”等表述，除非已经取得书面授权。

服务类目必须从账号后台当前可选列表中选择最贴近实际功能的项。不要仅因为场景在校园就选择需要学校资质的教育类目，也不要选择与实际功能不符的类目规避审核。

## 5. 隐私保护准备

当前版本需要在微信公众平台声明：

- 处理信息：用户主动选择的照片信息。
- 使用目的：创建、展示和编辑用户自己的校园回忆。
- 处理方式：复制到小程序本地用户目录；结构化日记保存在本地 Storage。
- 保存范围：仅当前设备、当前微信小程序本地数据空间，不上传项目自有服务器或 CloudBase。
- 拒绝影响：用户仍可创建纯文字回忆，但不能添加照片。
- 删除方式：逐条删除日记会清理日记数据和不再被引用的受管照片；“时光 → 数据管理”可二次确认后一键清除全部本机回忆、受管照片和个人资料。
- 明确不处理：GPS/真实地理位置、手机号、微信昵称头像、通讯录、好友关系、评论点赞。

可复制的填报草案见 `docs/PRIVACY_GUIDE_DRAFT.md`。最终内容必须由小程序实际运营主体核对并填写真实联系方式。

## 6. 发布候选版本冻结

在发布候选版本冻结前：

1. 确认 UI 和功能人工验收通过。
2. 检查 `git status` 和 `git diff`，把地图源图等授权证据与产品运行资产分开管理。
3. 执行：

   ```powershell
   npm.cmd ci
   npm.cmd run check
   ```

4. 在微信开发者工具执行“工具 → 构建 npm”。
5. 点击“编译”，确认 Console 没有资源 404、未处理 Promise、Storage 或文件系统异常。
6. 使用“代码依赖分析/代码质量”检查未使用文件和主包大小。
7. 当前工程版本号为 `0.9.0`，上传备注写清“本地数据公测版，不含云同步”。
8. 只有获得用户明确指令后才创建 Git 提交；不要把真实 AppID 或私人配置加入提交。

## 7. 体验版验收

1. 开发者工具点击“上传”，填写版本号和更新说明。
2. 微信公众平台进入“版本管理”，把该开发版本设置为体验版。
3. 添加体验成员，用 iOS 和 Android 分别扫描体验版二维码。
4. 按 `docs/MANUAL_TEST_CHECKLIST.md` 从空数据开始跑完整闭环。
5. 重点验证：
   - 首次隐私提示与拒绝相册后的纯文字流程；
   - 地图最大缩放后四角浏览和选点；
   - 1—3 张照片保存、重启读取、编辑换图和删除；
   - 时间搜索、地图筛选、个人资料和输入法遮挡；
   - 清除缓存/换手机时对本地数据限制的提示是否清楚；
   - 控制台没有未处理异常。

## 8. 提交审核材料

建议准备：

- 小程序简介：非官方个人校园记忆工具，支持地图选点、照片文字记录和时间回顾。
- 核心页面：地图页、日记编辑页、时光页、详情页。
- 审核路径：打开地图 → 记录此处 → 地图选点 → 填写纯文字或选择照片 → 保存 → 点击标记 → 查看详情 → 编辑/删除。
- 测试账号：当前版本无登录，不需要提供测试账号。
- 审核备注：数据默认仅保存于当前设备；无定位、支付、社交、内容公开或云端上传。
- 截图：使用无敏感信息、无版权争议、无不适内容的测试照片和文字。
- 隐私保护指引：与代码实际接口和产品说明一致。
- 资质/授权：若名称、地图或视觉素材被要求证明，能够提供来源与授权证据。

## 9. 提审与发布

1. 在微信公众平台“版本管理”选择已经完整验收的开发版本并提交审核。
2. 按页面填写服务类目、功能页面、标签、隐私说明和审核备注。
3. 审核期间不要继续修改并上传同一候选版本；新问题在单独分支修复。
4. 审核驳回时保存完整原因和截图，针对原因修改，不要通过隐藏真实功能规避审核。
5. 审核通过后先再次检查版本号和体验版，再点击发布。
6. 若平台提供分阶段发布能力，先小范围发布并观察启动、相册和文件保存异常，再扩大范围。

## 10. 上线后

- 记录发布日期、版本号、提交 SHA、开发者工具版本和基础库版本。
- 保留上一正式版本和回退说明。
- 用非开发者微信从搜索/扫码入口完成一次冷启动检查。
- 收集用户反馈时不要要求用户发送完整私人日记或照片；优先让用户提供错误提示、设备/微信版本和脱敏截图。
- 本地数据版无法由运营者远程恢复用户日记；客服说明必须诚实反映这一限制。
- 任何 CloudBase、登录、GPS、社交、分享可见范围等新增能力都必须重新更新隐私指引并重新提审。
