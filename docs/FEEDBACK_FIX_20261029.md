# 2026-10-29 日历、场景、头像与好友小屋修复

当前真实源码仍为 `3.2.0-rc.8`，本轮客户端增量尚未上传。既有存档、伙伴、日记和未提交功能保留。伙伴云服务已按本轮单独授权首次部署；客户端版本与云端部署分别记录。

## 日历白块

微信内置 `button[disabled]` 的浅白背景覆盖了日期格子的普通透明样式。加载期间所有日期被禁用，数据加载后未来日期仍被禁用，造成截图中的白矩形。

为 `button.mood-day[disabled]` 增加透明背景和继承文字颜色，保留加载防误触及未来日期限制。使用实际微信工具内置样式为夹具，三宽、默认/自定义背景及加载/未来日等30种组合通过。此修复去掉等待时的遮挡，不代表云端读取时间已缩短。

## 两个可走动场景

原银杏书屋和稷下暖庭包含固定角色及家具，将横版成图裁切填满手机屏幕会形成巨型角色与前景家具重叠。

本轮保留原图，基于原场景用ImageGen制作两张800×1100竖版空环境运行图：`ginkgo_playable_v2.jpg`、`jixia_playable_v2.jpg`。原稿在导航项目 `assets/pal-scene-rework-20261029`，尺寸/来源/哈希见 `COMPANION_PLAYABLE_SCENES_20261029.json`。窗边小屋沿用原图。

继续共享800×1100世界坐标。新行走目标和用户主动移动的地面家具限制在对应地面；宠物与普通家具使用一致的景深缩放和脚底阴影，命中同步做逆缩放。墙饰与地毯大小保留。旧存档坐标不迁移；新场景中位于地面的旧墙牌增加展示支架和接触影，牌子坐标、旋转和点击区域保持。

三宽×三场景×普通/缩放共18张实际Canvas浏览器截图通过，并核对真实图片尺寸、素材加载、画面覆盖及横向溢出。这是浏览器适配预览，不是微信原生或真机截图。

## 个人页头像

旧实现每33毫秒通过 `setData` 传递位移样式。主路径现用Canvas 2D节点 `requestAnimationFrame`，可用时缓存表情绘图，运动逐帧不再经过视图桥。头像环、首字、点击及平台隐私控制保留，Canvas不可用时使用兼容路径。

另修正轻倾斜尚未到重力平衡点就休眠、关闭运动未立即静止、重进时旧回调复活，以及原生帧调度/取消异常影响传感器释放的问题。共享Hub未改。

头像专项48项通过；三宽检查覆盖点击、12种表情配色、8个极限位置。浏览器合成动画逐帧 `setData` 为0；未测量手机帧率，不能当作真机60FPS证明。

## 好友小屋云服务

只读云端确认此前缺少 `companion-api` 及两个伙伴集合。用户明确授权后，仅新增伙伴函数、两张ADMINONLY集合及两索引。原auth/friend/memory三函数修改时间和完整包哈希保持。微信Windows CLI生成的子目录反斜杠包无法在Linux启动，已用官方接口更新为相同五文件的标准ZIP。

最终函数Active/Available、实际SDK4.0.2、五源哈希匹配；无身份真实云烟测返回 `UNAUTHENTICATED`。身份仍只取可信上下文，每次访问核验当前双向好友和开放状态，仅返回外观白名单。没有代用户开放小屋或读写用户内容。

`security.msgSecCheck` 声明随官方配置部署，但真实内容检测和手机双账号尚未验证；平台未暴露独立权限回读字段。证据在导航项目 `repairs-20261029/evidence/cloud/DEPLOYMENT_RESULT.json`。memory-api其他本地待部署增量未上线。
