# CloudBase 私密回忆与迁移配置

本文件对应 `memory-api` 和“备份本机回忆到云端”。在完成真实环境配置前，代码与自动测试完成不等于云端功能已经可用。

## 运行原则

- 未主动同意并完成迁移的用户继续使用 `LocalMemoryRepository`。
- 用户必须在“时光 → 数据管理”中主动选择“备份本机回忆到云端”。
- 迁移只处理 `origin=user` 的本机回忆，不上传 Demo 数据。
- 云端回忆默认全部为 `private`；迁移核验完全成功后才切换云端主数据。
- 部分失败时保留本地模式和全部本机副本，并列出失败记录供重试。
- 云端模式发生故障时会明确报错，不会静默回写本地，从而避免双主数据冲突。

## 需要创建的集合

以下集合都应设为“小程序端不可直接读写”，只允许云函数的管理端 SDK 操作：

- `users`
- `memories`
- `memory_migrations`
- `image_upload_plans`

创建唯一索引：

| 集合                | 字段           | 属性       |
| ------------------- | -------------- | ---------- |
| `users`             | `identityHash` | 唯一、升序 |
| `memory_migrations` | `migrationKey` | 唯一、升序 |

为常用查询创建普通索引：

| 集合                 | 字段                                     |
| -------------------- | ---------------------------------------- |
| `memories`           | `ownerUserId`, `deletedAt`, `recordedAt` |
| `image_upload_plans` | `ownerUserId`, `expiresAt`, `usedAt`     |

## 云存储规则

云存储不得开启公开读取。上传路径由 `memory-api` 创建一次性计划，格式为：

```text
users/<随机 iSdu userId>/memories/<uploadPlanId>/<imageId>.jpg
```

客户端不能自行指定所有者目录。云函数会检查上传计划、所有者、有效期、图片 ID 与最终 `fileID` 是否一致；数据库只保存 `fileID`，页面只接收经过服务端检查后生成的短期临时地址。

建议在 CloudBase 控制台将存储权限设为仅创建者可写且禁止公开读取。具体规则语法以当前控制台生成器为准，不要把环境 ID、AppID 或测试账号信息写入本文件。

## 部署步骤

1. 在微信开发者工具中关联测试 CloudBase 环境。
2. 按上文创建集合、索引和安全规则。
3. 先部署 `auth-api`，再部署 `memory-api`，均选择“云端安装依赖”。
4. 在数据管理页开启云端身份，确认只出现一条当前用户记录。
5. 准备一条纯文字、一条单图和一条多图本机回忆。
6. 点击“备份本机回忆到云端”，核对迁移数量与失败列表。
7. 重复执行迁移，确认没有生成重复回忆或重复图片引用。
8. 重启小程序，确认读取云端主数据；本机副本仍保留且没有被覆盖。

## 故障与回滚

- 上传或写入失败：保持本地模式，修复原因后重试。
- 本地图片丢失或数据损坏：失败条目不会被静默忽略；用户可修复或明确排除后再迁移。
- CloudBase 暂时不可用：云端模式显示错误，不在本机生成另一个同 ID 回忆。
- 需要回到比赛第一版：切回冻结的 `main` / `4f517e9`；不要覆盖该提交或比赛版标签。

## 尚需人工验证

- 真实 `wx.cloud.uploadFile` 的 iOS 与 Android 路径兼容性。
- 1—3 张照片在弱网、取消和部分上传失败时的恢复行为。
- 云存储规则是否确实阻止未授权直接下载。
- 主包大小、云函数冷启动和临时地址有效期表现。
